KDE Dialog Warning

Why kf.kio.widgets.kdirmodel: No node found for item that was just removed appears in the terminal, who prints it, and what the collector does about it.

Written 2026-09-22 after the messages were seen on Kubuntu 26.04 with Qt 6.10.2 and KDE Frameworks 6. Nothing was wrong with the program and no file was touched. The messages are muted in main() since that date.

What appears

Started from a terminal on a KDE desktop, the collector sometimes prints lines like these while it runs:

kf.kio.widgets.kdirmodel: No node found for item that was just removed: QUrl("file:///home/award/Downloads/chatgpt_amd64.deb")
kf.kio.widgets.kdirmodel: No node found for item that was just removed: QUrl("file:///home/award/Downloads/kubuntu_development_packages_install_guide.html")
kf.kio.widgets.kdirmodel: No node found for item that was just removed: QUrl("file:///home/award/Downloads/torrent_peer_discovery_gui_code_explanation_manual.html")

The files named are real files in the Downloads folder. None of them is a torrent, none was moved or deleted, and the collector's own code never refers to any of them.

Who prints it

The line is written from inside the collector's process, but not by the collector's code. The chain is:

  1. On a KDE desktop Qt loads KDE's platform integration plugin into every Qt application, so that dialogs, fonts and colours match the desktop.
  2. When the collector calls QFileDialog::getOpenFileName for the torrent file, that plugin substitutes the KDE file dialog for Qt's own.
  3. The KDE file dialog lives in the KIO library (libKF6KIOWidgets). Its file list is a KDirModel, fed by a KDirLister that lists and watches the folder.
  4. KDirModel logs under the category kf.kio.widgets.kdirmodel. Because it runs in the collector's process, its output lands on the collector's standard error, which is the terminal the program was started from.

You can confirm the KIO libraries are mapped into the running collector:

grep -c KIO /proc/$(pgrep -f build/libtorrent_peer_collector_qt)/maps

Any number above zero means KIO is loaded. Started with QT_QPA_PLATFORMTHEME=generic the count is zero, Qt's own dialog is used, and the messages never appear.

Why it is printed

The torrent dialog is opened with the name filter Torrent files (*.torrent). KDirLister reads the whole folder but hands the model only the entries that pass the filter, so a .deb or an .html file never gets a node in the model.

Later the listing is refreshed. That happens whenever the folder changes in any way, for example a download finishing or a browser writing a temporary file, and again whenever the dialog is opened a second time. On a refresh KIO re-applies the filter and reports every entry that does not match as removed. For an entry the model never inserted there is nothing to remove, and KDirModel logs exactly the line above.

In short: KIO reports the hiding of filtered-out files as removals to a model that never showed them. The files are untouched. The warning comes from KDE Frameworks and shows up in any Qt application that opens a filtered KDE file dialog from a terminal.

The same message can also be produced the honest way, when a file really is deleted or moved out of a watched folder that the model has not listed yet, for example between two openings of the dialog. Both cases are harmless.

What was done

One line in main(), right after the application is created, mutes that single logging category:

QLoggingCategory::setFilterRules("kf.kio.widgets.kdirmodel.warning=false");

The rule is as narrow as it can be:

  • It affects only the category kf.kio.widgets.kdirmodel and only its warning level.
  • Every other message from Qt, libtorrent, KIO's other components and the collector itself still prints.
  • It changes nothing about the dialog: the KDE look, the torrent filter and the folder memory stay as they were.

Alternatives that were not chosen

OptionEffectWhy not
Set QT_LOGGING_RULES="kf.kio.widgets.kdirmodel.warning=false" in the environmentSame silence, for every KDE application started from that shellHas to be set by whoever starts the program; the in-program rule needs nothing
Start with QT_QPA_PLATFORMTHEME=genericQt's own file dialog, KIO never loadedLoses the KDE dialog: places sidebar, previews, desktop look
Open the dialog without a name filterEvery file listed, so nothing is ever filtered out and reportedLoses the torrent-only listing, which is the point of the filter
Force Qt's dialog with QFileDialog::DontUseNativeDialogLike the generic theme, but only for this dialogSame loss of the KDE dialog, and inconsistent with the other dialogs

How to check the fix

  1. Build and start from a terminal: scripts/linux/build.sh && build/libtorrent_peer_collector_qt.
  2. Open the torrent dialog, pick a file, run a collection, open the dialog again.
  3. The terminal stays clean. Genuine warnings, should any occur, still print.
