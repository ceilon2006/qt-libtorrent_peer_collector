Build Requirements

What libtorrent_peer_collector_qt needs to compile and run, how to tell what is missing, and how to install it.

Verified on Ubuntu 26.04.1 LTS with Qt 6.10.2, libtorrent-rasterbar 2.0.12 and GCC, on 2026-09-20. The package names below are the ones that machine actually resolved.

What the project uses

The project is one C++17 source file built with qmake. Its .pro file declares everything it links:

QT += widgets core gui network
CONFIG += c++17 console link_pkgconfig
PKGCONFIG += libtorrent-rasterbar

So the build needs four Qt modules, the Qt build tools, a C++ toolchain, pkg-config, and the libtorrent development files. libtorrent in turn needs Boost headers and OpenSSL headers.

How to check what is missing

Run these from any directory. Each one should print a version; a "not found" or an error names the missing piece.

g++ --version                                    # build-essential
qmake6 -query QT_VERSION                         # qmake6-bin
pkg-config --modversion Qt6Widgets Qt6Network    # qt6-base-dev
ls /usr/lib/qt6/libexec/moc                      # qt6-base-dev-tools
pkg-config --modversion libtorrent-rasterbar     # libtorrent-rasterbar-dev

Or just run the build script. It checks for qmake, make, pkg-config and libtorrent before it starts and prints an install hint for whichever is missing:

scripts/linux/build.sh

Installing everything at once

Debian / Ubuntu

sudo apt update
sudo apt install build-essential qt6-base-dev libtorrent-rasterbar-dev

qt6-base-dev pulls in qmake6-bin and qt6-base-dev-tools. libtorrent-rasterbar-dev pulls in pkgconf, libboost-dev and libssl-dev. Nothing else is needed.

Fedora

sudo dnf install gcc-c++ make pkgconf-pkg-config qt6-qtbase-devel rb_libtorrent-devel

Arch

sudo pacman -S --needed base-devel pkgconf qt6-base libtorrent-rasterbar

Then build

scripts/linux/build.sh            # release build into build/
scripts/linux/build.sh debug      # debug build into build-debug/
scripts/linux/rebuild.sh          # clean first, then build
scripts/linux/clean.sh            # remove everything generated
scripts/linux/deploy.sh           # copy the executable to deploy/
scripts/linux/deploy.sh --install # install to ~/.local/bin with a menu entry

Or by hand:

qmake6 libtorrent_peer_collector_qt.pro
make

Windows

The Qt side is the same as for any Qt Widgets program. The difference is libtorrent: the Qt Online Installer does not ship it, and the .pro file finds it through pkg-config, which the Qt installer does not ship either.

Recommended: everything from MSYS2

MSYS2 packages Qt 6, libtorrent, Boost, OpenSSL, pkg-config and the MinGW toolchain, all built with the same compiler, so they link together without surprises.

  1. Install MSYS2 from msys2.org.
  2. Open the MSYS2 MINGW64 shell and install:
pacman -S --needed mingw-w64-x86_64-toolchain mingw-w64-x86_64-pkgconf \
    mingw-w64-x86_64-qt6-base mingw-w64-x86_64-qt6-tools \
    mingw-w64-x86_64-libtorrent-rasterbar
  1. Build from a normal Command Prompt with the MinGW64 bin folder on PATH, or straight from the MINGW64 shell:
set PATH=C:\msys64\mingw64\bin;%PATH%
scripts\windows\build.bat
scripts\windows\deploy.bat

deploy.bat runs windeployqt for the Qt DLLs and then copies libtorrent-rasterbar, libssl and libcrypto from the folder pkg-config --variable=prefix libtorrent-rasterbar points at. If MSYS2 only installs windeployqt6.exe, set QT_DEPLOY=C:\msys64\mingw64\bin\windeployqt6.exe first.

Alternative: Qt Online Installer plus your own libtorrent

Install these components in the Qt Maintenance Tool:

  • Qt 6.x → MinGW 64-bit (the prebuilt Qt libraries and qmake6)
  • Qt 6.x → Additional Libraries: nothing extra; Widgets and Network are part of the base module
  • Developer and Designer Tools → MinGW 13.x 64-bit (the compiler and mingw32-make)
  • Developer and Designer Tools → Qt Creator (optional)

libtorrent, Boost and OpenSSL must then come from somewhere else (vcpkg with the x64-mingw-dynamic triplet, or a source build) and must be compiled with a MinGW that is ABI-compatible with the one Qt ships. Mixing MSYS2's libtorrent with the Qt installer's Qt usually fails at link or start-up. That is why the all-MSYS2 route is recommended.

Whichever route you take, pkg-config.exe must be on PATH and PKG_CONFIG_PATH must contain the folder with libtorrent-rasterbar.pc. build.bat checks both and stops with a message if either is missing.

Qt Creator

Open libtorrent_peer_collector_qt.pro as a project. The kit must use a Qt 6 version and the same compiler the system libtorrent was built with, which on Linux is simply the distribution's GCC. Qt Creator runs qmake itself, so it needs pkg-config on its PATH; on Linux that is automatic once the packages above are installed.

The .qtcreator folder is kept in git, the build-* folders Qt Creator creates are not.
