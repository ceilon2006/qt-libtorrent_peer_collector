Build Requirements

What libtorrent_peer_collector_qt needs to compile and run, how to tell what is missing, and how to install it.

Verified on Ubuntu 26.04.1 LTS with Qt 6.10.2, libtorrent-rasterbar 2.0.12 and GCC, on 2026-09-20. The package names below are the ones that machine actually resolved.

What the project uses

The project is one C++17 source file built with qmake. Its .pro file declares everything it links:

QT += widgets core gui network
CONFIG += c++17 console link_pkgconfig
PKGCONFIG += libtorrent-rasterbar

So the build needs four Qt modules, the Qt build tools, a C++ toolchain, pkg-config, and the libtorrent development files. libtorrent in turn needs Boost headers and OpenSSL headers.

How to check what is missing

Run these from any directory. Each one should print a version; a "not found" or an error names the missing piece.

g++ --version                                    # build-essential
qmake6 -query QT_VERSION                         # qmake6-bin
pkg-config --modversion Qt6Widgets Qt6Network    # qt6-base-dev
ls /usr/lib/qt6/libexec/moc                      # qt6-base-dev-tools
pkg-config --modversion libtorrent-rasterbar     # libtorrent-rasterbar-dev

Or just run the build script. It checks for qmake, make, pkg-config and libtorrent before it starts and prints an install hint for whichever is missing:

scripts/linux/build.sh

Installing everything at once

Debian / Ubuntu

sudo apt update
sudo apt install build-essential qt6-base-dev libtorrent-rasterbar-dev

qt6-base-dev pulls in qmake6-bin and qt6-base-dev-tools. libtorrent-rasterbar-dev pulls in pkgconf, libboost-dev and libssl-dev. Nothing else is needed.

Fedora

sudo dnf install gcc-c++ make pkgconf-pkg-config qt6-qtbase-devel rb_libtorrent-devel

Arch

sudo pacman -S --needed base-devel pkgconf qt6-base libtorrent-rasterbar

Then build

scripts/linux/build.sh            # release build into build/
scripts/linux/build.sh debug      # debug build into build-debug/
scripts/linux/rebuild.sh          # clean first, then build
scripts/linux/clean.sh            # remove everything generated
scripts/linux/deploy.sh           # copy the executable to deploy/
scripts/linux/deploy.sh --install # install to ~/.local/bin with a menu entry

Or by hand:

qmake6 libtorrent_peer_collector_qt.pro
make

Installing Qt with the Qt Online Installer or Maintenance Tool

Instead of the distribution packages, Qt can come from Qt's own installer. That gives a newer Qt and a matching Qt Creator, and it is the normal way on Windows. The first install is done with the Qt Online Installer from qt.io/download-open-source; every later change goes through the Qt Maintenance Tool it leaves behind. Both need a free Qt account.

This section covers the Linux side and the component tree in general. The complete Windows procedure, including the extra Maintenance Tool components libtorrent needs, is in the Windows section.

The installer never provides libtorrent, Boost, OpenSSL headers or pkg-config. On Linux those still come from the distribution: sudo apt install build-essential libtorrent-rasterbar-dev. On Windows see the section below.

Pointing the build at the installer's Qt on Linux

The installer's qmake is called qmake, not qmake6, and it is not on PATH. Tell the build script where it is:

QMAKE=~/Qt/6.10.2/gcc_64/bin/qmake scripts/linux/build.sh

Or put the folder on PATH once per shell:

export PATH=~/Qt/6.10.2/gcc_64/bin:$PATH
scripts/linux/build.sh

qmake records the Qt library folder in the executable's rpath, so the built program finds that Qt at run time without any environment variable. The binary is then tied to that ~/Qt folder; to hand it to another machine, use the distribution packages instead.

If both a distribution Qt and an installer Qt are present, scripts/linux/build.sh prints which one it used in its qmake: and Qt version: lines.

Which route to choose on Linux

  • Distribution packages when you just want to build and run. One apt install, everything matches, and the binary runs on any machine with the same packages.
  • Qt installer when you need a newer Qt than the distribution ships, or want Qt Creator and Qt kept in step. libtorrent still comes from the distribution either way.

Windows

The Qt side is the same as for any Qt Widgets program and is installed with the Qt Maintenance Tool. The difference is libtorrent: the Maintenance Tool does not ship it, and the .pro file finds it through pkg-config, which the Maintenance Tool does not ship either. So a Windows build is: Qt and the toolchain from the Maintenance Tool, libtorrent built once from source with that same toolchain, and a small pkg-config.exe so qmake can find it.

The Windows scripts default to the Maintenance Tool layout: C:\Qt\6.11.1\mingw_64, C:\Qt\Tools\mingw1310_64 and C:\Qt\Tools\OpenSSLv3\Win_x64. Set QMAKE, MAKE, MINGW_BIN or OPENSSL_BIN if your versions differ. These steps follow the pattern used for the sibling Qt projects on this machine but have not been run from this repository on Windows.

Step 2: Boost headers

libtorrent 2.0 needs only the Boost headers, no compiled Boost libraries. Download the boost_1_xx_0.zip archive from boost.org and extract it so that C:\boost\boost\asio.hpp exists. Nothing to build.

Step 3: build libtorrent once with Qt's MinGW

Open a Command Prompt, put Qt's toolchain first on PATH, and build a shared libtorrent into C:\libtorrent:

set PATH=C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\CMake_64\bin;C:\Qt\Tools\Ninja;%PATH%

git clone --branch RC_2_0 --depth 1 --recurse-submodules https://github.com/arvidn/libtorrent.git C:\src\libtorrent
cd C:\src\libtorrent

cmake -S . -B build -G Ninja ^
    -DCMAKE_BUILD_TYPE=Release ^
    -DBUILD_SHARED_LIBS=ON ^
    -DCMAKE_INSTALL_PREFIX=C:/libtorrent ^
    -DBOOST_ROOT=C:/boost ^
    -DOPENSSL_ROOT_DIR=C:/Qt/Tools/OpenSSLv3/Win_x64 ^
    -Dpython-bindings=OFF -Dbuild_tests=OFF -Dbuild_examples=OFF -Dbuild_tools=OFF

cmake --build build
cmake --install build

The install writes C:\libtorrent\bin\libtorrent-rasterbar.dll, the headers, and C:\libtorrent\lib\pkgconfig\libtorrent-rasterbar.pc. That .pc file carries the compile definitions libtorrent was built with, which is why the project reads it through pkg-config instead of hard-coding paths: the definitions must match or the program will not work.

Build libtorrent with the same MinGW the Maintenance Tool installed for Qt. A libtorrent from MSYS2, vcpkg's default triplets or another GCC uses a different C runtime or standard library and will fail to link or crash at start-up.

Step 4: pkg-config

Any small pkg-config.exe works; it only has to read the .pc file. Two easy sources:

choco install pkgconfiglite

or download pkg-config-lite from SourceForge and put pkg-config.exe somewhere on PATH. Then tell it where the libtorrent .pc file is, for the current shell or permanently in the system environment variables:

set PKG_CONFIG_PATH=C:\libtorrent\lib\pkgconfig
pkg-config --modversion libtorrent-rasterbar

Step 5: build and deploy the project

scripts\windows\build.bat            rem release into build\
scripts\windows\build.bat debug      rem debug into build-debug\
scripts\windows\rebuild.bat          rem clean, then build
scripts\windows\clean.bat            rem remove everything generated
scripts\windows\deploy.bat           rem deploy\ with all DLLs, ready to copy elsewhere

build.bat finds qmake and MinGW in the default Maintenance Tool folders on its own. It checks for pkg-config.exe and for libtorrent-rasterbar before it starts and stops with a message naming what is missing.

deploy.bat runs windeployqt for the Qt DLLs, then copies libtorrent-rasterbar.dll from C:\libtorrent\bin (found through pkg-config --variable=prefix) and the two OpenSSL DLLs from the Maintenance Tool's OpenSSL folder. Override with LIBTORRENT_BIN or OPENSSL_BIN if they live elsewhere. The resulting deploy\ folder runs on a machine with nothing installed.

Alternative: everything from MSYS2

If you would rather not build libtorrent yourself, MSYS2 packages Qt 6, libtorrent, Boost, OpenSSL, pkg-config and a MinGW toolchain, all built together. Install MSYS2 from msys2.org, open the MSYS2 MINGW64 shell and run:

pacman -S --needed mingw-w64-x86_64-toolchain mingw-w64-x86_64-pkgconf \
    mingw-w64-x86_64-qt6-base mingw-w64-x86_64-qt6-tools \
    mingw-w64-x86_64-libtorrent-rasterbar

Then build with the MinGW64 bin folder first on PATH so the scripts pick up MSYS2's qmake, compiler and pkg-config instead of the Maintenance Tool ones:

set PATH=C:\msys64\mingw64\bin;%PATH%
set QT_DEPLOY=C:\msys64\mingw64\bin\windeployqt6.exe
scripts\windows\build.bat
scripts\windows\deploy.bat

Do not mix the two routes. Qt from the Maintenance Tool with libtorrent from MSYS2, or the other way round, does not link.

Qt Creator

Open libtorrent_peer_collector_qt.pro as a project. The kit must use a Qt 6 version and the same compiler the system libtorrent was built with, which on Linux is simply the distribution's GCC. Qt Creator runs qmake itself, so it needs pkg-config on its PATH; on Linux that is automatic once the packages above are installed.

The .qtcreator folder is kept in git, the build-* folders Qt Creator creates are not.
